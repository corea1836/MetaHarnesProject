# 식자·합성

이미지 모델은 한글을 정확히 그리지 못하므로, 이 하네스는 글자를 그림에 그리지 않고 HTML로 얹는다. 덕분에 대사·말풍선을 고칠 때 그림을 다시 생성할 필요 없이 콘티의 `balloons`만 고치고 다시 합성하면 된다. 합성은 몇 초면 끝난다.

## 합성 실행

```bash
node .claude/skills/webtoon-lettering/scripts/compose_episode.mjs \
  --storyboard _workspace/04_director_storyboard.json \
  --panels _workspace/05_artist_panels \
  --select _workspace/05_selected.json \
  --out _workspace/06_compose
```

| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `--select` | 없음 | `{ "p01": "p01_v2.png" }` 형식. 검수를 통과한 버전을 고른다. 없으면 각 패널의 가장 높은 버전을 쓴다. |
| `--width` | 800 | 출력 가로(px). 콘티의 여백·글자 크기는 이 값에 비례한다. |
| `--slice` | 1280 | PNG 조각 하나의 최대 세로(px). 800×1280은 많이 쓰는 플랫폼 업로드 한도다. 올릴 플랫폼의 규격이 다르면 바꾼다. |
| `--split` | `fixed` | 조각 나누는 방식. `fixed`는 `--slice` 높이마다(웹툰 플랫폼 업로드), `panels`는 칸 경계마다(커뮤니티 썸네일·이미지를 한 장씩 넘기는 SNS. 첫 조각이 곧 첫 컷이고 칸과 그 말풍선이 한 조각에 남는다), `none`은 전체 한 장(커뮤니티 본문). |
| `--strips-dir` | `strips` | 조각을 저장할 하위 폴더. 분할 방식을 여러 개 만들 때 폴더를 나눈다(예: `strips_panels`, `strips_full`). |
| `--max-gap` | 없음 | 이번 PNG 출력에서만 칸 사이 여백을 이 높이(px)로 줄인다. 이어 읽을 때의 리빌 여백이 한 장씩 보는 SNS 조각에서는 빈 화면이 되기 때문이다. 뷰어와 콘티는 바뀌지 않는다. |

### 게시처별 출력

게시처마다 독자가 이미지를 보는 방식이 달라서, 한 가지 분할로는 모든 곳에 맞출 수 없다. 사용자가 게시처를 말하지 않았으면 앞의 두 가지를 만든다.

| 게시처 | 옵션 | 이유 |
|--------|------|------|
| 커뮤니티·X·인스타처럼 이미지를 한 장씩 보거나 첫 이미지가 썸네일이 되는 곳 | `--split panels --max-gap 80 --strips-dir strips_sns` | 첫 조각이 곧 첫 컷이라 어떤 크롭에도 썸네일이 맞고, 칸과 그 말풍선이 한 조각에 남는다 |
| 한 장만 올릴 수 있는 곳 | `--split none --strips-dir strips_full` | 리빌 여백까지 그대로 살린 세로 한 장. 썸네일은 플랫폼 크롭에 따라 첫 컷이 아닐 수 있다 |
| 웹툰 플랫폼(조각을 이음매 없이 이어 붙이는 뷰어) | `--split fixed`(기본) | 업로드 규격(800×1280) 준수. 조각 경계가 말풍선을 자르는지 반드시 열어 보고, 자르면 `--slice`를 조정한다 |
| `--html-only` | | PNG 조각을 만들지 않는다. 빠르게 배치만 확인할 때 쓴다. |
| `--allow-missing` | | 이미지가 없는 패널을 빨간 자리표시로 채운다. 일부 패널이 실패했어도 전체 흐름을 미리 볼 때 쓴다. |

산출물: `episode.html`(브라우저 뷰어, 좁은 화면에서도 비율 유지), `panels/`, `strips/strip_001.png …`, `layout.json`(총 높이, 조각 수, 누락 패널).

종료 코드: 0 성공 · 1 입력 오류 또는 패널 누락 · 2 Chrome 없음·렌더링 실패. Chrome이 다른 경로에 있으면 `CHROME_PATH` 환경 변수로 지정한다.

## 합성 뒤 확인

`strips/`의 PNG를 Read로 **모두** 열어 본다. 숫자나 HTML만 보고 판단하지 않는다. 글자 배치 문제는 렌더링된 화면에서만 보인다.

| 문제 | 고치는 곳 |
|------|----------|
| 말풍선이 얼굴·손·핵심 소품을 가린다 | 해당 말풍선의 `x`, `y`를 빈 공간 쪽으로 옮기거나, `placement`를 `gutter-before`/`gutter-after`로 바꾼다 |
| 말풍선이 패널 밖으로 넘친다 | `w`를 넓혀 줄 수를 줄이거나 `y`를 올린다. 대사가 길면 여백으로 옮긴다 |
| 꼬리가 엉뚱한 사람을 가리킨다 | `tail` 방향을 화자 쪽으로 바꾼다 |
| 읽는 순서가 헷갈린다 | 먼저 할 말을 위·왼쪽으로 옮긴다 |
| 효과음이 얼굴을 가린다 | `sfx`의 `x`, `y`를 동작 근처의 빈 곳으로 옮긴다 |
| 장면 사이 호흡이 너무 짧거나 길다 | `gap_before`를 조정한다 |

콘티를 고친 뒤에는 검사(`validate_storyboard.mjs`)와 합성을 다시 실행한다. 조각 경계에서 말풍선이 잘리는 것은 정상이다. 플랫폼 뷰어가 조각을 이어 붙여 보여 준다.

## 말풍선 종류 고르기

| type | 모양 | 쓰임 |
|------|------|------|
| `speech` | 흰 둥근 풍선 + 꼬리 | 일반 대사 |
| `thought` | 점선 타원 + 동그라미 꼬리 | 속마음 |
| `shout` | 굵은 테두리, 큰 글씨, 살짝 기울어짐 | 외침·놀람 |
| `whisper` | 가는 점선, 회색 작은 글씨 | 속삭임·혼잣말 |
| `electronic` | 이중 테두리, 푸른 바탕 | 전화·방송·문자·로봇 |
| `narration` | 그림 위: 크림색 사각 상자 / 여백: 테두리 없는 글줄 | 해설·독백·시간 표시 |

대사를 고치는 요청이면 글콘티(`02_writer_script.md`)도 함께 고쳐 두 문서가 어긋나지 않게 한다.
