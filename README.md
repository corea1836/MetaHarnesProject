# 단편 웹툰 제작 하네스

아이디어 한 줄을 받아 **기획 → 설정집 → 글콘티 → 연출 콘티 → AI 작화 → 식자·합성**을 거쳐 세로 스크롤 웹툰(HTML 뷰어 + 게시용 PNG 조각)을 만드는 Claude Code 에이전트 팀이다. 작가·편집자·캐릭터 디자이너·연출가·작화가·검수자 역할의 서브에이전트 6종과, 이들을 조율하는 오케스트레이터 스킬로 이루어져 있다.

### 무엇이 달랐나

| 장면 | 하네스 | 단일 채팅 | 차이를 만든 장치 |
|---|---|---|---|
| 요청 해석 | 메인 에이전트가 밈을 웹에서 조사해 요청서로 정리했다. "원작 대사를 한 줄도 안 바꿔도 여자 말포이가 된다"는 팬덤 담론을 찾아 기획 재료로 넘겼다 | 소재 이름만 보고 바로 그렸다 | 오케스트레이터 1단계(요청 정리), 에이전트의 웹 검색 도구 |
| 기획 의도 확인 | 그리기 전에 후보 3개를 비교표로 보여 주고 사용자가 골랐다. 이미지 비용도 작화 전에 확인받았다 | 먼저 그린 뒤, 사용자가 결과를 보고 고쳐 달라고 했다 | 확인 1(기획), 확인 2(비용) |
| 이야기 | 원작 명대사 "아버지가 아시게 될 거야"를 그대로 썼는데, 말하는 사람이 딸이 되자 협박이 짝사랑 고백의 증거로 뒤집혔다. 성별 반전이 펀치를 만든다 | 1차는 헤르미온느를 의식하는 츤데레 전개를 시도했다. "말포이 같지 않다"는 피드백을 받자 악역 대사만 키웠고("내 아버지가 누군지 알면, 넌 내 발밑에 기어야 할 텐데"), "이목을 끌어야" 피드백에는 이야기를 그대로 두고 이펙트만 더했다 | 작가와 편집자 분리. 피드백이 위치·근거·수정 방향을 갖춘 필수/권장 표로 오간다 |
| 편집 검토 | 그리기 전에 잡았다. 삼각붕대에 건 팔을 "치켜드는" 모순, 교복 입은 10대 소녀를 로우 앵글로 잡는 구도의 위험(→ 웨이스트숏, 로브 여밈), 대사에 "말포이"라는 이름이 한 번도 없어 퍼 나르면 정체가 사라지는 문제, 실존 배우를 닮을 위험 | 해당 단계 없음 | 편집자 에이전트(`webtoon-review`) |
| 패널 검수 | 썸네일 컷이 대칭의 온화한 미소로 나오자, 검수자가 말포이 특유의 거만한 비웃음(턱을 들고 한쪽 입꼬리만 올림)으로 두 번 다시 그리게 했다. 썸네일에서 말포이로 알아보게 하는 정체 신호이기 때문이다(아래 그림) | 도서관 컷의 헤르미온느가 슬리데린 넥타이와 문장을 달고 있다. 위 컷에서는 그리핀도르였다 | 기준 시트와 대조하는 검수자(`panel-inspector`), PASS/FIX/REDO 판정 |
| 정책 대응 | 흉터를 "lightning bolt"로 묘사하자 이미지 API가 거부했다. 디자이너가 "zigzag scar"로 바꿔 다시 생성했다. 그림에는 고유명사와 문장을 넣지 않는다 | 학교 문장과 이름을 그림에 그대로 그렸다 | 설정집의 `alias_en` 규칙, 종료 코드별 대응 |
| 글자 | 대사를 HTML로 얹는다. 대사만 고칠 때는 그림을 다시 그리지 않는다 | 글자가 그림에 박혀 있다. 부제는 잘렸다 | 식자 스크립트(`compose_episode.mjs`) |
| 형식 | 요청대로 3컷 세로 조각. SNS에서는 첫 장이 곧 첫 컷이다 | 3컷을 요청했는데 가로 4컷 한 장이 나왔다. 폰에서는 글자가 작다 | 게시처별 출력(`--split panels`) |

### 단일 채팅이 나은 점

- **빠르고 싸다.** 대화 한 번에 몇 초가 걸렸다. 하네스는 1화에 약 1시간, 이미지 9장(기준 시트 4장 + 패널 5장)을 썼다.
- **한눈에 해리 포터로 읽힌다.** 기숙사 문장과 해리·론·헤르미온느 삼인방이 그대로 나온다. 하네스는 정책 때문에 문장과 이름을 그림에서 뺐다. 그래서 인물의 정체를 녹색·은색 대 진홍·금색의 색 대비와 대사로 알려야 했고, 1화 편집자는 화면 앞 소년이 해리라는 신호가 약하다고 지적했다.
- **한글 대사를 그림 안에 거의 정확히 그렸다.**

### 비교 조건과 한계

- **모델도 다르다(Claude와 Gemini).** 위 표에는 하네스의 어느 장치에서 나왔는지 기록으로 추적되는 차이만 적었다. 그래도 모델 차이를 완전히 떼어 낸 실험은 아니다. 같은 모델의 단일 채팅과 비교하면 더 분명해진다.
- **"어그로·유입"이라는 목적은 Claude Code 쪽 첫 요청에만 있었다.** Gemini에는 세 번째 턴에 전달했다.
- **밈 조사는 하네스 규칙이 아니라 메인 에이전트의 판단이었다.** 같은 결과를 재현하려면 오케스트레이터 1단계에 조사 단계를 규칙으로 넣어야 한다.
- **비교는 한 번뿐이다.**

## 동작 방식

메인 에이전트가 `webtoon-orchestrator` 스킬을 따라 팀을 조율한다. 단계마다 편집자 검토와 사용자 확인을 거치고, 비용이 드는 작화 직전에는 콘티와 설정집을 해시로 동결한다.

```mermaid
flowchart LR
    A[0~1 요청 정리<br/>API 점검] --> B[2 기획<br/>writer ⇄ editor]
    B --> C1[3 글콘티<br/>writer ⇄ editor]
    B --> C2[3 설정집·기준 시트<br/>designer]
    C1 --> D[4 연출 콘티<br/>director ⇄ editor<br/>규약 검사 · 동결]
    C2 --> D
    D --> E[5 작화<br/>artist 1~3 병렬<br/>inspector 검수]
    E -->|FIX / REDO<br/>패널당 최대 2회| E
    E --> F[6 식자·합성<br/>스크립트]
    F --> G[7 최종 검수<br/>editor]
    G --> H[8 납품<br/>output/slug/]
```

| 단계 | 하는 일 | 실행 방식 |
|------|---------|-----------|
| 1 요청 정리 | 아이디어·톤·분량·피할 요소를 정리하고 이미지 API를 점검한다. 키가 없으면 자리표시 그림으로 끝까지 가는 dry-run을 제안한다 | 메인 |
| 2 기획 | 로그라인·인물·비트 시트를 쓰고, 편집자 지적을 최대 2회 왕복으로 반영한다 | 지속형 에이전트 |
| 3 설정집 ‖ 글콘티 | 화풍·캐릭터 외형 앵커와 기준 시트 이미지, 컷 단위 각본을 **병렬**로 만든다 | 서브에이전트 + 지속형 |
| 4 연출 콘티 | 컷별 샷·앵글·패널 크기·여백·말풍선 위치와 작화용 영어 프롬프트를 `storyboard.json`으로 정하고 `validate_storyboard.mjs`로 검사한다 | 지속형 에이전트 |
| 5 작화 | 기준 시트를 참조 이미지로 넘겨 패널을 그리고, 검수자가 PASS/FIX/REDO를 판정한다. 절반 이상이 같은 이유로 REDO면 재생성을 멈추고 설정집부터 고친다 | 작화가 병렬 + 단발 검수자 |
| 6 식자·합성 | 말풍선·효과음을 얹어 HTML 뷰어와 게시처별 PNG 조각을 만든다 | 스크립트 |
| 7 최종 검수 | 완성본을 보고 필수 수정을 담당자별로 나눠 1회 반영한다 | 지속형 에이전트 |
| 8 납품 | `output/{slug}/`에 완성본과 기획·콘티·설정집을 모은다 | 메인 |

## 사용법

### 준비

- [Claude Code](https://claude.com/claude-code)
- Node.js(외부 패키지 의존성 없음)
- Google Chrome: 합성 단계에서 HTML을 PNG로 렌더링한다. 기본 위치에 없으면 `.env`의 `CHROME_PATH`로 지정한다
- OpenAI API 키

```bash
cp .env.example .env   # OPENAI_API_KEY 입력
node .claude/skills/webtoon-panel-art/scripts/generate_image.mjs --check
```

### 요청 예

이 폴더에서 Claude Code를 열고 말로 요청한다.

- "새벽 편의점 알바생이랑 매일 오는 고양이 이야기로 10컷 웹툰 만들어줘. 따뜻하고 살짝 웃기게."
- "세 컷짜리 인스타툰으로, 확인 없이 끝까지 만들어줘."

만든 웹툰은 필요한 단계만 다시 실행해 고친다.

| 요청 예 | 다시 하는 단계 | 새로 그리는 이미지 |
|---------|---------------|-------------------|
| "대사 더 짧게", 오타, 말풍선 위치 | 식자·합성 | 없음 |
| "3번 컷 표정만 다시" | 해당 패널 작화 → 합성 | 해당 컷 |
| 구도·컷 순서 변경 | 콘티 → 바뀐 패널 작화 → 합성 → 검수 | 바뀐 컷 |
| "주인공 머리를 단발로" | 설정집 → 그 인물이 나오는 패널 전부 | 해당 컷 전부 |
| "결말 바꿔줘" | 글콘티 → 콘티 → 바뀐 패널 | 바뀐 컷 |
| "같은 캐릭터로 2화" | 이전 설정집을 재사용해 새로 제작 | 새 화 전부 |

## 산출물

```
output/{slug}/
├── episode.html     브라우저용 세로 스크롤 뷰어
├── strips_sns/      커뮤니티·X·인스타용 칸별 조각(첫 조각 = 첫 컷 = 썸네일)
├── strips_full/     한 장짜리 세로 이미지
├── strips/          웹툰 플랫폼용 800×1280 고정 분할(요청 시)
├── panels/          말풍선 없는 원본 패널
├── concept.md       기획안
├── script.md        글콘티
├── storyboard.json  연출 콘티
└── bible/           설정집과 기준 시트
```

작업 중간 산출물은 `_workspace/`에 남고, 저장소에는 올리지 않는다.
